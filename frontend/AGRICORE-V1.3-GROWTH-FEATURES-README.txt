AgriCore v1.3 — Growth Features Sprint

AUDIT-FIRST RESULT
This package was built from the latest uploaded AgriCore frontend.
It does NOT rebuild Calendar, Dispatch, Service Programmes, Billing, Communications,
Offline mode, Data Management, Core Deletion Engine, Theme Engine or existing dashboard widgets.
It extends the current architecture.

FEATURE 1 — GLOBAL SEARCH / COMMAND PALETTE
- Ctrl+K / Cmd+K from anywhere in the authenticated app.
- Mobile search button in the top bar.
- Searches the ACTIVE COMPANY only.
- Searches customers, machines, jobs, quotes, invoices, stock and users.
- Financial search results are hidden from financially restricted field roles.
- Technician/apprentice search is restricted to their own jobs rather than exposing company-wide customer/financial directories.
- Quick navigation/actions are available when the search field is empty.
- No new external search service is required.

FEATURE 2 — CUSTOMISABLE WORKSHOP DASHBOARD
- Uses the EXISTING dashboard widgets rather than building a second dashboard.
- Users can:
  * drag widgets to reorder them
  * hide/show widgets
  * choose small / medium / large / full width
  * restore the default layout
- Layout is saved per COMPANY + USER and follows the user across devices.
- Subscription and onboarding banners remain outside the customisable layout so critical notices cannot be accidentally hidden.
- Financial widgets remain permission-aware.

FEATURE 3 — AI WORKSHOP ASSISTANT
- Replaces the old placeholder AI Diagnostics page with a real Service Intelligence workspace.
- Select an existing company machine.
- Enter symptoms, fault codes and technician context.
- Automatically loads up to 20 recent jobs for that machine plus relevant parts and labour history.
- If OPENAI_API_KEY is configured, uses the OpenAI Responses API.
- Default model: gpt-5.6 (override with OPENAI_MODEL).
- If no OpenAI key is configured, the page still works in HISTORY-ONLY mode and summarises AgriCore repair history without making an external AI call.
- Diagnostic prompt explicitly:
  * treats suggestions as advisory
  * refuses to invent manufacturer torque/pressure/fault-code specifications
  * tells technicians to verify safety-critical/manufacturer information
  * does not claim access to proprietary manuals or bulletins
- Customer identity is not included in the OpenAI diagnostic payload.
- Existing ai_diagnostics.use permission is retained.
- AI Diagnostics is enabled for Professional and Enterprise plans by the migration.

FEATURE 4 — ENTERPRISE MACHINERY SALES CRM
New /sales module for Enterprise subscriptions.
Professional/Starter subscription companies cannot elevate this module with a feature override.
Internal/demo companies retain full platform access for testing/presentation.

Includes:
- Sales pipeline / opportunities
- Lead → Qualified → Quoted → Negotiation → Won/Lost stages
- Estimated value + probability / weighted pipeline
- Existing AgriCore customer linking
- Machinery stock inventory
- New / Used / Ex-demo condition
- Incoming / Available / Workshop / Reserved / Sold status
- Cost and asking price
- Trade-in appraisal records
- Trade-ins can link directly to an existing customer machine, reusing its recorded identity/details
- Sales permissions:
  * sales.view
  * sales.manage
- Role editor updated to expose the new permissions
- Navigation item only appears when BOTH plan entitlement and user permission allow it

OPENAI ENVIRONMENT (AI FEATURE)
Optional for local/history-only testing; required for live AI reasoning:

OPENAI_API_KEY=<your OpenAI API key>
OPENAI_MODEL=gpt-5.6

OPENAI_MODEL is optional. If omitted, AgriCore uses gpt-5.6.
Never put OPENAI_API_KEY in NEXT_PUBLIC_* variables or browser code.
Add it server-side to .env.local for local development and to Vercel Environment Variables for production.

NO NEW NPM DEPENDENCIES
The AI integration uses server-side fetch against the OpenAI Responses API, so this sprint does not add another JavaScript SDK dependency.

INSTALL
1. Run the Supabase migration above.
2. Extract this ZIP over:
   C:\projects\Agricore\frontend
3. For AI, add OPENAI_API_KEY locally if you want to test live AI reasoning.
4. Run:

taskkill /F /IM node.exe
Remove-Item ".next" -Recurse -Force -ErrorAction SilentlyContinue
npm.cmd run build
npm.cmd run dev -- --webpack
